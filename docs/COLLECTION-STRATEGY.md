# 수집 전략 — 차단되지 않고 자료를 모으는 방법

> 관련: [§3 출처·수집·검증 정책](spec/02-sources.md) · [부록 A 출처 레지스트리](spec/A-source-registry.md) · 미결 항목 ②

## 결론 먼저

**HTML 크롤링이 막히는 건 대부분 "잘못된 문을 두드려서"다.**
이 프로젝트가 필요로 하는 A/B등급 출처는 거의 전부 **공식 OPEN API 또는 RSS를 제공한다.**
API로 바꾸면 차단을 우회할 필요 자체가 없어지고, 데이터 품질도 올라간다.

| | HTML 크롤링 | 공식 OPEN API |
| --- | --- | --- |
| 차단 | 자주 막힘 | 막히지 않음 (인증키 기반) |
| 구조 변경 | 사이트 개편마다 파서 깨짐 (§15.4 최상위 리스크) | 스키마 안정 |
| 데이터 | 본문 텍스트만 | 시행일·공포일·의안번호·개정이력이 **필드로** 제공 |
| 첨부 | 별도 스크래핑 | 다운로드 URL 제공 |
| 법적 | 이용약관 검토 필요 | 이용 허락 명시 |
| 재배포 | 불명확 | 공공누리 라이선스 명시 |

두 번째 행이 특히 중요하다. AI가 시행일을 **추론**하지 않고 API 필드에서 **직접** 가져오면,
§9.4 V2(근거 없는 날짜 금지)와 AT-05를 구조적으로 만족한다. 환각 위험이 사라진다.

## 하지 않는 것

명세서 §3.4가 이미 정하고 있고, 이 프로젝트는 그대로 따른다.

> robots.txt 우회, 로그인 우회, 과도한 요청, 캡차 우회는 **구현하지 않는다.**
> API가 없거나 자동수집이 불안정한 출처는 수동·메일 기반 운영으로 대체한다.

즉 IP 로테이션, User-Agent 위장, 캡차 자동 해제, 로그인 세션 탈취,
차단 탐지 회피는 만들지 않는다. 이유는 세 가지다.

1. **제품 자체를 무너뜨린다.** 세무 정보 서비스의 자산은 신뢰다. 정부기관과 마찰이 생기면
   서비스가 멈춘다. 세무사무소 B2B 고객(§11.6)은 그 리스크를 안고 계약하지 않는다.
2. **필요가 없다.** 아래 표대로 대부분 공식 경로가 있다.
3. **더 나쁜 데이터를 만든다.** 회피 크롤링은 불안정해서 누락이 생기고,
   누락은 "발표됐는데 안 알려준" 사고로 이어진다.

## 출처별 수집 경로

부록 A의 19개 출처를 수집 방식으로 다시 정리했다.
**URL과 API 제공 여부는 구현 직전에 재확인해야 한다**(부록 A 원칙, 미결 ②).

### A등급 — 공식 API 확인됨

| 출처 | 경로 | 얻는 것 |
| --- | --- | --- |
| 국가법령정보센터 | [국가법령정보 공동활용 OPEN API](https://open.law.go.kr/LSO/openApi/guideList.do) | 현행법령 목록·본문, **시행일 법령 목록**, 법령 변경이력, 조문 단위 개정 이력, 판례·해석례 |
| 국회 의안정보 | [열린국회정보 OPEN API](https://open.assembly.go.kr/portal/openapi/main.do) | 의안 통합정보, 발의 이유·주요내용, 본회의 표결, HWP/PDF 첨부 |
| 전자관보 | 관보 검색 + 첨부 PDF | 공포 사실과 공포일 |

**국가법령정보 공동활용의 "시행일 법령 목록"과 "법령 변경이력"이 이 제품의 심장이다.**
§3.2 `legal_status`의 `PROMULGATED`/`EFFECTIVE` 판정과 §9.4 V3(A등급 근거 필수)를
추론 없이 확정할 수 있다. 이 API 하나로 AT-04·AT-05가 데이터 레벨에서 해결된다.

### B등급 — 공공데이터포털 / RSS / 메일

| 출처 | 우선 경로 | 대체 |
| --- | --- | --- |
| 국세청 | [공공데이터포털](https://www.data.go.kr) 국세청 제공 API, 보도자료 RSS | 메일링 구독 → EMAIL 어댑터 |
| 재정경제부 | 보도자료 RSS | 정책브리핑 경유 |
| 정책브리핑(korea.kr) | RSS (부처 보도자료 통합) | — |
| 기업마당 | 공공데이터포털 지원사업 공고 API | RSS |
| 소상공인24 | 공고 목록 | 수동 등록 |
| 고용노동부 | 보도자료 RSS | 정책브리핑 경유 |
| 4대보험 기관 (건보·연금·근로복지) | 공지·보도자료 RSS | 수동 등록 |
| 위택스·지자체 | 공고 (기관별 편차 큼) | **수동 등록 기본** |

공공데이터포털은 필요한 API가 목록에 없으면 **제공 신청**을 할 수 있다.
MVP 착수 시 국세청 보도자료·세무일정을 신청 대상으로 올린다.

### C/D등급 — 뉴스

RSS만 수집하고 **제목·요약·링크만 저장한다.** 전문을 저장·재배포하지 않는다(§NFR-015).
용도는 탐지뿐이며, 발송하려면 A/B 원문을 붙여야 한다(게이트 G1, AT-03).

## 그래도 막힐 때

API도 RSS도 없는 출처(주로 지자체)는 아래 순서로 내려간다.

1. **저빈도 정중한 수집** — robots.txt를 지키고, `rate_limit_per_min`을 낮게 잡고,
   `If-Modified-Since`/`ETag`로 변경분만 받는다. 이미 `sources` 테이블에 필드가 있다.
2. **메일 구독** — 기관 뉴스레터를 전용 주소로 받아 `collector_type=EMAIL`로 처리한다.
   차단이 없고 기관이 의도한 배포 경로다.
3. **수동 등록** — `POST /api/v1/raw-contents/manual`. **이미 구현되어 있고 AT-01/AT-02를 통과한다.**
   운영자가 URL·본문을 붙여넣으면 해시·버전·중복 판정이 자동으로 돌아간다.
4. **해당 출처 비활성화** — `sources.status`를 내리고 대시보드에 표시한다.
   조용히 누락되는 것보다 "이 출처는 지금 안 들어온다"가 보이는 게 낫다.

3번이 있기 때문에 자동수집이 막혀도 서비스는 멈추지 않는다.
이것이 §15.4에서 "공식 사이트 구조 변경 → 수동등록"을 완화책으로 둔 이유다.

## 착수 순서

| 단계 | 할 일 | 산출물 |
| --- | --- | --- |
| 1 | 국가법령정보 공동활용 API 신청 | 인증키 |
| 2 | 열린국회정보 API 신청 | 인증키 |
| 3 | 공공데이터포털 가입 + 국세청 관련 API 신청 | 인증키 |
| 4 | 기관별 RSS 주소 실측 (19개 출처) | 부록 A 갱신 |
| 5 | 각 출처 이용약관·공공누리 등급 기록 | `sources.terms_url`, `copyright_policy` |
| 6 | 자동/메일/수동 판정 확정 | 미결 ② 종결 |

1~3은 신청 후 승인까지 시간이 걸릴 수 있으므로 **가장 먼저** 시작한다.
5번은 법률 검토 대상이며(§12.4), 재배포 가능 범위를 여기서 확정한다.

## 코드에 이미 반영된 것

- `sources` 테이블에 `collector_type`(API/RSS/HTML/EMAIL/MANUAL), `rate_limit_per_min`,
  `terms_url`, `copyright_policy`, `schedule_cron` — 출처마다 다르게 운영할 수 있다.
- **출처를 코드에 하드코딩하지 않는다**(부록 A). 기관이 개편해도 DB만 고친다.
- SSRF 방어([`app/core/ssrf.py`](../backend/app/core/ssrf.py)) — 허용 도메인, 사설 IP 차단,
  리다이렉트 매 홉 재검사 (AT-14).
- 수동 등록 경로 완비 — 자동수집이 죽어도 운영이 계속된다.
