- 출력: 웹 화면(오늘/일정/찾기 + 상세) · 매일 아침 텔레그램 2통
- 규모: 백엔드 FastAPI+SQLAlchemy 15,097줄 / 프론트 Next.js+React 4,557줄
- DB: PostgreSQL(Neon, us-east-2) · 표 29개 · 행 6,531 · **Alembic** 사용

## 3. 프론트엔드 (제일 중요)

taxbriefing 화면은 **React** 이고 이쪽은 **Vue 3** 이라 그대로 못 옮깁니다.
다시 짜야 해서 이쪽 규칙을 알아야 합니다.

3-1. **사이드바 메뉴 정의 위치**(파일:줄)와 항목 하나 추가하는 최소 절차.

3-2. **공용 컴포넌트가 있습니까?** 카드·버튼·배지·표·빈 화면·로딩 등.
     있으면 목록과 경로, 없으면 "없다".

3-3. **Tailwind 설정.** 색·간격·글꼴을 따로 정의했습니까? 색 토큰 이름이
     있습니까? (taxbriefing 은 `ink`/`line`/`accent`/`danger` 를 씁니다.)

3-4. **모바일에서 씁니까?** 반응형이 돼 있습니까, 사무실 PC 전용입니까.

3-5. Pinia 스토어가 몇 개이고 무엇을 담습니까.

3-6. 목록 화면 하나(`Notices.vue` 또는 `Clients.vue`)가 데이터를 불러와 그리는
     전체 흐름을 짧게 보여 주세요.

## 4. 거래처 (합치는 진짜 이유)

taxbriefing 은 "이 개정이 어느 고객에게 해당하는가" 를 못 잇습니다.
이쪽 `clients` · `client_assignees` 와 이으면 **"김실장이 맡은 거래처 중
음식점 3곳에 해당하는 개정"** 을 뽑을 수 있습니다.

4-1. `clients` 에 **몇 건**이 있습니까. 담당자가 지정된 것은 몇 건입니까.

4-2. **업종 정보가 어딘가에 있습니까?** `client_type` 은 법인/개인/기타로
     보입니다. 업종(음식점·학원·도소매…)을 적는 칸이 따로 있습니까,
     `memo` 같은 자유 입력에 섞여 있습니까?

4-3. 업종 칸을 새로 만든다면 **누가 언제 채웁니까?** 거래처 등록 화면이
     어디이고 누가 씁니까.

4-4. `client_assignees` 의 주담당/부담당과 `released_at` 이력을 설명해 주세요.
     "지금 이 사람이 맡은 거래처 목록" 질의가 이미 있습니까?
