# 12. 보안·개인정보·감사

> 원본: 통합개발명세서 §12

## 12.1 데이터 등급

| 등급 | 예시 | 통제 |
| --- | --- | --- |
| 공개 | 정부 원문, 공개 정책정보 | 출처·라이선스 메타 유지 |
| 내부 | AI 프롬프트, 운영 메모, 검수 기록 | 직원 권한 제한 |
| 개인정보 | 이름, 이메일, 전화, 사업자 프로필 | 암호화, 목적·보유기간, 접근로그 |
| 민감 운영정보 | API 키, 발송 공급자 키 | Secret Manager, **DB 저장 금지** |
| 감사 데이터 | 승인·수정·발송 이력 | 삭제 제한, 무결성 보호 |

## 12.2 RBAC

| 역할 | 허용 | 금지 |
| --- | --- | --- |
| `VIEWER` | 운영현황·콘텐츠 조회 | 수정·발송 |
| `EDITOR` | 원문 연결·콘텐츠 편집 | **최종 승인** |
| `REVIEWER` | 검수·승인·반려 | 권한·출처 설정 |
| `CAMPAIGN_MANAGER` | 대상·템플릿·예약발송 | **전문가 승인 우회** |
| `TENANT_ADMIN` | 자사 브랜드·고객그룹 | 다른 테넌트 조회 |
| `SYSTEM_ADMIN` | 출처·권한·시스템 설정 | 검수 책임 자동 대체 불가 |

추가 역할 `SUBSCRIBER` (일반 구독자)는 `users.role` 기본값이며 관리 API 접근 권한이 없다.

> **SYSTEM_ADMIN도 검수를 대체할 수 없다.** 승인은 `REVIEWER` 역할만 수행 가능하며,
> 관리자가 자기 자신에게 REVIEWER를 부여하는 행위는 감사로그에 남는다.

구현: [`app/core/rbac.py`](../../backend/app/core/rbac.py) — 엔드포인트별 `require_role()` 의존성

## 12.3 보안 통제

- 관리자 MFA와 비정상 로그인 알림
- API 인증·인가를 **각 엔드포인트에서** 검증
- DB와 객체스토리지 저장 암호화, TLS 전송
- 개인정보·토큰·비밀키 로그 마스킹
- 파일 업로드 MIME 확인, 크기 제한, 악성파일 검사, 실행 금지
- SQL/HTML 인젝션 방지와 출력 이스케이프
- 외부 URL 수집 시 **SSRF 방지**: 허용 도메인, 사설 IP 차단, 리다이렉트 제한
- 테넌트 ID 기반 데이터 격리와 테스트
- 관리자 다운로드와 대량조회 감사로그
- 정기 취약점 점검과 의존성 스캔

### SSRF 방어 사양 (AT-14)

수집기는 아래를 **모두** 통과한 URL만 요청한다.

1. 스킴이 `http`/`https`
2. 호스트가 `sources.canonical_domain` 허용 목록에 포함
3. DNS 해석 결과가 사설·예약 대역이 아님
   (`10/8`, `172.16/12`, `192.168/16`, `127/8`, `169.254/16`, `::1`, `fc00::/7`, `fe80::/10`, `0.0.0.0/8`)
4. 리다이렉트는 최대 3회, **매 홉마다 1~3을 재검사**

구현: [`app/core/ssrf.py`](../../backend/app/core/ssrf.py)

## 12.4 개인정보·수신동의

- 서비스 제공 동의와 **마케팅 수신동의를 구분**
- 이메일·알림톡·SMS **채널별** 동의 시각과 문구 버전 저장
- 철회 즉시 미래 캠페인 대상에서 제외 (AT-10)
- 탈퇴·파기 요청 처리와 법정 보존 데이터 분리
- 사업자 프로필은 개인화를 위한 **최소 항목만** 수집
- 개인정보보호법, 전자적 광고 규정, 통신사·채널 정책은 **출시 전 법률 검토**

> 동의 확인은 캠페인 생성 시점이 아니라 **발송 실행 시점**에 재확인한다.
> 예약 후 발송 전에 철회한 사용자가 최종 대상에서 빠져야 하기 때문이다 (AT-10).
