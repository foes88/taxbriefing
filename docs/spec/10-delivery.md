# 11. 발송·개인화·과금

> 원본: 통합개발명세서 §11

## 11.1 개인화 규칙 축

| 규칙 축 | 예시 |
| --- | --- |
| 사업자 유형 | 개인사업자, 법인, 프리랜서, 비영리 |
| 과세 유형 | 일반과세, 간이과세, 면세 |
| 세목 | 부가세, 소득세, 법인세, 원천세, 지방세 |
| 업종 | 음식, 온라인판매, 제조, 병의원, 임대, 서비스 |
| 고용 | 직원 없음, 1~4명, 5명 이상 |
| 지역 | 전국, 시도, 시군구 |
| 기업 규모 | 매출구간, 중소기업 여부 |
| 관심 | 지원사업, 정책자금, 노무, 신고일정 |

## 11.2 매칭 가중치 (초기값)

| 항목 | 가중치 |
| --- | --- |
| 직접 대상 일치 | +40 |
| 세목/주제 일치 | +20 |
| 업종 일치 | +15 |
| 지역 일치 | +15 |
| 마감 7일 이내 | +20 |
| 사용자 관심/저장 행동 | +5 |
| **명시적 제외 대상** | **-100** |
| 읽음 후 관심없음 | -20 |

> 실제 가중치는 운영 데이터로 조정하며, 초기에는 규칙 기반으로 시작한다.
> 모델 기반 추천을 도입하더라도 **명시적 제외와 법적 상태 제한을 우선한다.**

구현: [`app/domain/personalization.py`](../../backend/app/domain/personalization.py)
`-100`은 단순 감점이 아니라 **하드 제외**로 구현한다 (AT-08). 다른 가중치 합이 아무리 커도 대상에 포함되지 않는다.

## 11.3 발송 유형

| 유형 | 조건 | 발송 |
| --- | --- | --- |
| 긴급 (`URGENT`) | 신고기한 변경, 시스템 장애, 중대 시행 변경 | 승인 즉시. 야간 정책 예외는 운영 승인 |
| 일일 (`DAILY`) | 지난 24시간 승인 콘텐츠 | 평일 아침 또는 사용자 설정 |
| 주간 (`WEEKLY`) | 발의·예고·해설·동향 | 주 1회 |
| 마감 알림 (`DEADLINE`) | 사용자 관련 마감 D-7/D-1 | 중복 방지 |
| 정정 (`CORRECTION`) | 오류 또는 정책 변경 | 영향 대상에게 즉시 또는 우선 발송 |

## 11.4 채널 정책

- **이메일**: 상세 브리핑, 원문 링크, **수신거부 링크 필수**
- **알림톡**: 승인된 템플릿과 변수만 사용, 상세는 웹 링크
- **SMS**: 긴급·마감 중심, 최소 정보와 수신거부 안내
- **웹**: 전체 근거와 정정 이력을 보존하는 기준 화면

각 채널의 발송 내용은 `content_version`과 발송 시점 스냅샷(`deliveries.message_snapshot`)으로 **고정 저장**한다.
콘텐츠가 이후 수정되어도 "무엇을 보냈는지"는 변하지 않아야 한다 (AT-12, AT-15).

## 11.5 멱등성 키 규칙

```
deliveries.idempotency_key = "{campaign_id}:{user_id}:{channel}"
```

동일 키로 재요청하면 새 발송을 만들지 않고 기존 `delivery`를 반환한다 (AT-09).

## 11.6 요금제

| 플랜 | 기능 |
| --- | --- |
| 무료 | 일반 브리핑, 주요 신고일정, 제한된 주제 |
| 개인사업자 | 업종·지역 맞춤, 마감 알림, 저장·상담 |
| 법인 | 다중 담당자, 원천세·노무, 주간 리포트 |
| 세무사무소 B2B | 화이트라벨, 고객그룹, 상담전환, 성과분석 |
| 엔터프라이즈 | SSO, API, 전용 출처·템플릿, SLA |

> 과금(FR-BIL-001)은 `COULD` 우선순위이며 MVP 후반 또는 2단계다.
> 결제대행사·환불정책은 [`docs/OPEN-DECISIONS.md`](../OPEN-DECISIONS.md) 미결 항목 ⑤.
