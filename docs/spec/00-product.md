# 1. 제품 정의와 성공 기준

> 원본: `TaxBriefing_통합개발명세서_v1.0.docx` §1 · 문서 버전 v1.0 · 기준일 2026-08-06

## 1.1 한 줄 정의

TaxBriefing은 국세·지방세·노무·4대보험·소상공인·기업지원 관련 신규 정보를 탐지하고, 공식 원문으로 사실을 확인한 뒤, 사업자 유형별 영향과 행동사항을 전문가 검수 후 발송하는 **B2B2C 정보 서비스**다.

## 1.2 해결하는 문제

- 정부와 공공기관 정보가 여러 사이트에 분산되어 있어 사업자가 매일 확인하기 어렵다.
- 기사 제목만으로는 정책이 검토·발의·공포·시행 중 어느 단계인지 알기 어렵다.
- 현재 적용 기준과 변경 예정 기준이 혼재되어 잘못된 의사결정을 유발한다.
- 사업자 유형·업종·지역에 따라 관련성이 다르지만 기존 뉴스는 개인화가 약하다.
- 세무사무소가 고객에게 지속적으로 유용한 정보를 제공하면서 상담으로 연결할 운영 도구가 부족하다.

## 1.3 제품 원칙 (구현 불변식)

| 원칙 | 구현 기준 |
| --- | --- |
| 공식 원문 우선 | 뉴스는 탐지·맥락 용도이며 확정 판단은 법령, 관보, 정부기관 원문으로 수행한다. |
| 상태 분리 | 콘텐츠 처리 상태와 정책의 법적 상태를 별도 필드로 관리한다. |
| 근거 없는 생성 금지 | AI는 원문에 없는 숫자, 날짜, 대상, 예외를 생성하지 않는다. |
| 사람이 최종 승인 | 세금 계산, 적용대상, 가산세, 신고의무 등 고위험 항목은 전문가 승인 없이는 발송하지 않는다. |
| 추적 가능성 | 원문 버전, 수집 시각, 분석 모델, 수정자, 승인자, 발송본을 보존한다. |
| 정정 우선 | 정책 변경이나 오류 발견 시 영향대상에게 정정 메시지를 발송하고 이전 콘텐츠와 연결한다. |

> 이 6개 원칙은 코드 레벨에서 강제되어야 하며, 우회 경로가 존재하면 결함으로 취급한다.
> 대응 구현: [`app/domain/gates.py`](../../backend/app/domain/gates.py), [`app/domain/workflow.py`](../../backend/app/domain/workflow.py)

## 1.4 MVP 성공 지표

| 지표 | MVP 목표 | 측정 방식 |
| --- | --- | --- |
| 공식 원문 연결률 | 발송 콘텐츠 100% | `content_sources`에 A/B등급 공식 근거 1개 이상 |
| 고위험 콘텐츠 전문가 승인률 | 100% | review 상태와 승인자 로그 |
| 수집 성공률 | 주요 출처 일평균 98% 이상 | `source_runs` 성공/실패 지표 |
| 중복 콘텐츠 감소율 | 원본 대비 60% 이상 병합 | 클러스터 전후 건수 |
| 발송 오류율 | 0.5% 이하 | 채널별 provider 결과 |
| 정정 소요시간 | 중대 오류 인지 후 2시간 이내 | incident 및 correction 타임스탬프 |
| 이메일 열람률 | 초기 베이스라인 35% 이상 | 채널 분석 이벤트 |

## 1.5 문서 관리 규칙

| 항목 | 내용 |
| --- | --- |
| 문서 소유자 | 서비스 운영사 / 제품책임자 |
| 승인권자 | 세무전문가 책임자 및 제품책임자 |
| 개정 주기 | MVP 개발 중 주 1회, 운영 전환 후 월 1회 또는 법령·채널 변경 시 |
| 변경관리 | Git 또는 문서관리시스템에서 버전 태그와 변경이력 관리 |
| 우선순위 규칙 | 본문과 부속 파일이 충돌하면 본 문서의 최신 승인 버전을 기준으로 함 |

## 1.6 개발 전 반드시 확정할 항목 (미결)

1. 발송 채널 사업자 및 계약조건
2. 공식 출처별 자동수집 허용 방식
3. 전문가 검수 SLA
4. 개인정보 처리방침·마케팅 수신동의 문구
5. 유료화 시 결제대행사와 환불정책

→ 진행 상태는 [`docs/OPEN-DECISIONS.md`](../OPEN-DECISIONS.md)에서 추적한다.
