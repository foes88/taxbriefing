## B.2 v1.0 계약 검토 결과 요약

패키지를 코드로 옮기며 확인한 계약 간 불일치를 한곳에 모은다. 상세는 각 장에 있다.

| 구분 | 항목 | 위치 |
| --- | --- | --- |
| DB 초안 | D-01 ~ D-08 (8건) | [7.4 데이터 모델](06-data-model.md#74-초안-ddl에서-확인된-이슈와-구현-결정) |
| API 계약 | A-01 ~ A-07 (7건) | [8.4 API 명세](07-api.md#84-초안-계약에서-확인된-불일치와-구현-결정) |
| AI 스키마 | S-01 ~ S-06 (6건) | [9.4 AI 명세](08-ai.md#스키마-계약에서-확인된-이슈와-구현-결정) |

**가장 중요한 3건**

1. **A-01** — 본문 예시(`checked_source_ids`)와 OpenAPI(`checked_source_version_ids`)가 다르다.
   검수자가 확인한 대상이 *원문*인지 *원문 버전*인지가 달라지며, 추적성(§1.3)이 걸린 문제다. → 버전으로 통일.
2. **A-04** — `ContentCreate`가 `legal_status`를 required로 요구하지만, 콘텐츠 생성 시점에는 원문 확인 전이다.
   `UNKNOWN`을 허용하지 않으면 운영자가 아무 값이나 넣게 되어 §1.3 "상태 분리"가 무너진다.
3. **S-03** — §9.1은 `missing_reason`을 필수라고 하나 AI 출력 스키마에 해당 필드가 없다.
   `warnings[].code='MISSING_EVIDENCE'`로 대체하되, 명세 문구를 스키마에 맞춰 정정해야 한다.
