# API 신청 가이드 — 어디서 무엇을 신청하는가

> 관련: [수집 전략](COLLECTION-STRATEGY.md) · [부록 A 출처 레지스트리](spec/A-source-registry.md) · 미결 항목 ②
> 확인일 2026-08-06. **정부 사이트는 개편되므로 신청 직전에 화면을 다시 확인한다**(부록 A 원칙).

## 순서

1. **국가법령정보 공동활용** — 가장 먼저. 이게 제품의 심장이고 승인에 시간이 걸린다
2. **공공데이터포털** — 한 번 가입하면 여러 기관 API를 여기서 신청한다
3. **열린국회정보** — 의안 발의 단계를 다룰 때
4. **RSS** — 가입 불필요. 주소만 확인하면 바로 쓴다

---

## 1. 국가법령정보 공동활용 (A등급 · 최우선)

법제처가 운영한다. **시행일·공포일·법령 변경이력을 필드로** 주기 때문에,
AI가 시행일을 추론하지 않고 그대로 가져올 수 있다. §9.4 V2와 AT-05가 데이터 레벨에서 해결된다.

| | |
| --- | --- |
| 사이트 | https://open.law.go.kr |
| 회원가입 | https://open.law.go.kr/LSO/usrJoin.do |
| API 신청 | https://open.law.go.kr/LSO/openApi/cuAskList.do |
| 활용가이드 | https://open.law.go.kr/LSO/openApi/guideList.do (총 191개 API) |
| 문의 | 02-2109-6446 |

### 신청할 API

전체 191개 중 아래만 신청하면 된다. 나머지는 필요할 때 추가한다.

| 순위 | API | 쓰는 곳 |
| --- | --- | --- |
| ★★★ | **현행법령(시행일) 목록 조회** | 시행 예정·시행 중 법령 탐지. `legal_status = EFFECTIVE` 판정 |
| ★★★ | **현행법령(시행일) 본문 조회** | 조문 원문 확보. `content_evidence`의 근거 |
| ★★★ | **법령 변경이력 목록 조회** | 개정 탐지. UC-05 정책 변경 추적 |
| ★★ | **일자별 조문 개정 이력 목록 조회** | "무엇이 달라졌는가"(`changes`) 생성 |
| ★★ | **조문별 변경 이력 목록 조회** | 조문 단위 diff |
| ★★ | **현행법령(공포일) 목록·본문 조회** | `legal_status = PROMULGATED` 판정, 공포일 확보 |
| ★ | **행정규칙 목록·본문 조회** | 고시·훈령·예규 (국세청 고시가 여기 있다) |
| ★ | **법령해석례 목록·본문 조회** | 실무 해석. 발송이 아니라 검수자 참고용 |
| — | 판례 목록·본문 조회 | MVP 제외. 개별 사안 판단은 범위 밖(§2.3) |

### 인증 방식 — `OC` 는 직접 정한다

발급받는 키가 아니라 **신청 화면에서 사용자가 직접 지정하는 식별자**다.
신청서의 `API인증키(OC)` 칸에 원하는 값을 넣고 중복확인을 누른다.
신청 후에는 마이페이지 → API인증키관리에서 확인한다.

```
https://www.law.go.kr/DRF/lawSearch.do?OC=taxbriefing&target=eflaw&query=소득세법
                                          ↑ 직접 정한 값
```

- 목록조회 `lawSearch.do` · 본문조회 `lawService.do`
- `target` 값이 어떤 API를 부를지 고른다 (`eflaw` = 현행법령 시행일 기준)

**작명 기준**

- 짧고 흔한 값(`tax`, `test`)은 이미 선점됐을 가능성이 크다
- `OC`는 **URL 쿼리스트링에 그대로 노출된다.** 비밀번호가 아니라 식별자다.
  다만 **호출 한도가 이 값에 묶이므로** 뻔한 값을 쓰면 남이 갖다 써서 한도를 소모할 수 있다
- 권장: `taxbriefing`

**보관**

프론트엔드에서 법령 API를 직접 호출하지 않는다. 백엔드에서만 호출하고,
값은 `TAXBRIEFING_LAW_API_OC` 환경변수로 주입한다(§12.1). 설정 자리는 이미 만들어져 있다.

## 2. 공공데이터포털 (B등급 다수)

한 번 가입하면 국세청·기업마당 등 여러 기관 API를 여기서 신청한다.

| | |
| --- | --- |
| 사이트 | https://www.data.go.kr |
| 이용가이드 | https://www.data.go.kr/ugs/selectPublicDataUseGuideView.do |

### 절차

1. **회원가입** — 일반회원 또는 기업회원, 이메일 인증
2. **인증키 발급** — 마이페이지 → API 키 발급/관리 → 일반 인증키.
   발급 후 **활성화까지 1~2시간** 걸린다
3. **활용신청** — API 상세 페이지의 `활용신청` 버튼. 활용 목적과 라이선스 동의를 입력.
   자동승인은 즉시, 심사 대상은 **1영업일 이내**
4. **키 확인** — 마이페이지 → 오픈API → 인증키 발급현황.
   **Encoding / Decoding 두 가지**가 나온다. 라이브러리가 URL 인코딩을 하는지에 따라 골라 쓴다

> 신청은 **PC에서만** 된다. 모바일에서는 버튼이 비활성화된다.

### 신청할 API

| API | 쓰는 곳 | 비고 |
| --- | --- | --- |
| **기업마당 지원사업 공고** | 지원사업 신청기간·대상. §11.3 마감 알림 | 기업마당 자체 API도 있음 (아래) |
| 국세청 제공 API | 목록을 보고 보도자료·세무일정 관련이 있으면 신청 | 확인된 것은 사업자등록 상태조회뿐 |
| 중소벤처기업부 기업마당 정책뉴스 | 지원사업 동향 | 선택 |

> **국세청 보도자료·세무일정 API는 현재 목록에 없을 수 있다.**
> 공공데이터포털은 **제공 신청**(없는 데이터를 개방해 달라는 요청)을 받는다.
> 목록에 없으면 제공 신청을 올리고, 그동안은 RSS·수동 등록으로 운영한다.

### 기업마당 직접 API

공공데이터포털을 거치지 않는 경로도 있다. 둘 중 편한 쪽을 쓴다.

- API 목록 https://www.bizinfo.go.kr/apiList.do
- 지원사업정보 API https://www.bizinfo.go.kr/apiDetail.do?id=bizinfoApi
- JSON·XML, GET 방식

## 3. 열린국회정보 (A등급 · 의안)

법안이 발의만 된 단계(`BILL_PROPOSED`)를 추적할 때 필요하다.
"국회 통과했다"는 뉴스가 나왔을 때 실제 의결 여부를 확인하는 용도이기도 하다.

| | |
| --- | --- |
| 사이트 | https://open.assembly.go.kr/portal/openapi/main.do |
| API 목록 | https://open.assembly.go.kr/portal/openapi/openApiNaListPage.do |

### 신청할 API

| API | 쓰는 곳 |
| --- | --- |
| **의안 통합정보** | 의안번호·발의일·소관위원회·처리결과 |
| **의안 제안이유 및 주요내용** | `changes` 초안 생성 |
| 국회의원 발의법률안 | 발의 단계 탐지 |
| 본회의 표결정보 | `ASSEMBLY_PASSED` 판정 |

의안 첨부(HWP/PDF)도 API로 받을 수 있다.

## 4. RSS (가입 불필요 · 지금 바로 시작 가능)

**이게 가장 빠른 출발점이다.** 신청 승인을 기다릴 필요가 없다.

| 기관 | RSS 페이지 |
| --- | --- |
| 대한민국 정책브리핑 | https://www.korea.kr — 구독&참여 → RSS 서비스 |
| 국세청 | https://www.nts.go.kr — 알림·소식 → 보도자료 |
| 고용노동부 | https://www.moel.go.kr |
| 국민연금·건강보험·근로복지공단 | 각 기관 공지·보도자료 |

> **정확한 피드 주소는 확인하지 못했다.** 정책브리핑 RSS 페이지가 메인으로 리다이렉트되고,
> 국세청은 RSS 주소를 공개 페이지에서 찾지 못했다.
> 각 사이트에서 직접 확인해 `sources` 테이블에 등록한다.
> RSS가 없으면 메일 구독(`collector_type=EMAIL`) 또는 수동 등록으로 내려간다.

**정책브리핑 하나가 여러 부처 보도자료를 모아준다.** 기관별로 붙이기 전에 여기부터 시작하면
국세청·기재부·고용노동부를 한 번에 커버할 수 있다.

## 신청 시 적을 활용 목적

대부분 "활용 목적"을 요구한다. 아래 문구를 쓰면 된다.

> 사업자(개인사업자·법인)를 대상으로 세무·노무·지원사업 관련 공식 발표 정보를 수집하여,
> 정책의 법적 상태(발의·예고·공포·시행)와 시행일을 정확히 구분해 안내하는 정보 서비스를 개발합니다.
> 원문 링크와 출처를 함께 제공하며, 세무전문가 검수를 거쳐 발송합니다.

## 라이선스 확인

신청과 함께 **재배포 조건**을 확인해 `sources.copyright_policy`에 기록한다(§NFR-015, 미결 ④).

- 공공누리 제1~4유형 중 어디에 해당하는가
- 출처 표시 방식
- 상업적 이용 가능 여부 (B2B 화이트라벨에 영향)
- 변형·2차 가공 가능 여부 (AI 요약이 여기 해당)

## 체크리스트

- [ ] 국가법령정보 공동활용 가입
- [ ] `OC` 값 정하기 (권장 `taxbriefing`) → 중복확인
- [ ] 법령 API 9종 신청 (위 ★ 목록)
- [ ] `.env`에 `TAXBRIEFING_LAW_API_OC` 설정
- [ ] 공공데이터포털 가입 + 일반 인증키 발급
- [ ] 기업마당 지원사업 공고 API 활용신청
- [ ] 국세청 관련 API 목록 확인 (없으면 제공 신청)
- [ ] 열린국회정보 가입 + 의안 API 신청
- [ ] RSS 주소 실측 (정책브리핑 우선)
- [ ] 각 출처 공공누리 등급 기록
- [ ] `sources` 테이블 `status`를 `PENDING_REVIEW` → `ACTIVE` 로 전환

마지막 항목이 미결 ②의 종결 조건이다.
