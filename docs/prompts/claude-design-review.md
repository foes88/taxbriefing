# Claude 검증용 프롬프트 — TaxBriefing 개발명세서 v1.0

아래 파일을 모두 함께 읽고, 개발 착수 전 설계 검증을 수행해 주세요.

- `TaxBriefing_통합개발명세서_v1.0.docx`
- `TaxBriefing_schema.sql`
- `TaxBriefing_openapi_draft.yaml`
- `TaxBriefing_ai_output_schema.json`

## 역할
당신은 한국의 세무·정책 정보 플랫폼을 검증하는 시니어 제품 아키텍트, 백엔드 아키텍트, AI 품질 엔지니어, 보안 리뷰어입니다. 정확한 공식 원문 확인과 전문가 검수를 최우선 가치로 봅니다.

## 검증 목표
1. 이 문서만으로 개발팀이 MVP 구현을 시작할 수 있는지 판단합니다.
2. PRD, 기능 요구사항, DB, API, AI JSON Schema 사이의 모순과 누락을 찾습니다.
3. 세무·정책 정보의 법적 상태를 잘못 표시하거나 뉴스만으로 확정하는 경로가 있는지 찾습니다.
4. AI가 원문에 없는 날짜·수치·대상·행동을 생성할 가능성을 줄이는 구체적 수정안을 제시합니다.
5. 12주 MVP에 과도한 범위를 분리하고 첫 3개 스프린트 백로그를 만듭니다.

## 필수 검토 항목
- 콘텐츠 워크플로 상태와 정책 법적 상태의 분리 및 상태 전이
- 공식 출처 A/B 등급 게이트와 뉴스 C/D 등급 사용 제한
- 원문 버전, 근거 위치, 승인, 정정, 발송 스냅샷의 추적 가능성
- 수집·AI·캠페인·발송 멱등성
- 날짜 필드의 의미와 null 처리
- HWP/PDF/첨부파일 처리 실패 시 수동 대체
- 사용자 개인화에서 제외 대상 우선 처리
- 수신동의·철회·파기와 광고성 정보 발송 통제
- RBAC, 관리자 MFA, SSRF, 파일 업로드, 테넌트 격리
- 저작권: 뉴스 전문 저장·재배포 위험
- 관측성, 백업·복구, 장애·정정 프로세스
- 인수 테스트가 핵심 위험을 충분히 검증하는지

## 출력 형식
### 1. 총평
- 개발 착수 가능: 예 / 조건부 / 아니오
- 가장 큰 장점 3개
- 가장 큰 위험 5개

### 2. 치명적 문제
표 형식: `ID | 파일/섹션 | 문제 | 영향 | 구체적 수정안`

### 3. 스키마·API 불일치
SQL, OpenAPI, AI JSON Schema와 본문 요구사항을 비교하여 누락 필드, 잘못된 enum, FK·unique·인덱스, 권한 문제를 지적합니다.

### 4. 세무정보 정확성 통제 리뷰
뉴스 단독 발송, 정책상태 오분류, 시행일 오인, 적용대상 과장, 전문가 승인 우회 가능성을 시나리오로 공격 테스트합니다.

### 5. 보안·개인정보·저작권 리뷰
위험도와 우선순위를 포함합니다.

### 6. MVP 축소안
- 12주에 반드시 구현할 것
- 2단계로 미룰 것
- 제거할 것

### 7. 수정된 스프린트 백로그
2주 스프린트 기준 3개 스프린트에 대해 Epic, Story, Acceptance Criteria, 의존성을 작성합니다.

### 8. 추가 결정이 필요한 질문
최대 15개. 단순 확인이 아니라 구현을 막는 질문만 작성합니다.

### 9. 최종 승인 체크리스트
개발 착수 전에 사람이 승인해야 할 항목을 체크박스로 제공합니다.

## 검증 규칙
- 모호한 표현은 그대로 두지 말고 교체 문구 또는 필드 정의를 제시합니다.
- “추가 검토 필요”만 쓰지 말고 무엇을 누가 언제 결정해야 하는지 명시합니다.
- 한국 세법의 구체적인 최신 내용 자체를 추정하지 말고, 제품의 검증·표시·운영 통제를 검토합니다.
- 구현 제안은 가능한 한 표준적이고 공급자 교체가 가능한 구조로 작성합니다.
