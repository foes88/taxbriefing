# TaxBriefing 웹

Next.js 16 + Tailwind. 공개 사이트와 관리자 화면이 한 앱에 있다.

## 실행

```bash
cd frontend
npm install
npm run dev          # http://localhost:3100
```

백엔드가 먼저 떠 있어야 한다 (`http://localhost:8000`).
다른 주소를 쓰려면 `NEXT_PUBLIC_API_BASE` 를 설정한다.

## 화면

| 경로 | 화면 | 인증 |
| --- | --- | --- |
| `/` | 오늘의 브리핑 (U-02) — 카드 목록, 검색·필터 | **없음** |
| `/contents/[id]` | 콘텐츠 상세 (U-03) — §10.3 표준 블록 | **없음** |
| `/admin/login` | 관리자 로그인 | — |
| `/admin` | 운영 대시보드 (A-01) | 필요 |
| `/admin/raw` | 수집 원문 목록 (A-03) | 필요 |
| `/admin/raw/[id]` | 원문 상세 → 콘텐츠 생성 (A-04) | 필요 |
| `/admin/contents/[id]` | 검수 편집기 (A-05) — 게이트 판정 표시 | 필요 |
| `/admin/sources` | 출처 관리 (A-02) | 필요 |

로그인이 없는 것은 의도된 설계다 (ADR-002). 텔레그램 링크로 들어온 사업자가
회원가입 없이 바로 읽을 수 있어야 한다.

## 로컬 계정

```
admin / admin1234        운영자·최고관리자
reviewer / reviewer1234  검수자
```

**승인은 검수자만 가능하다.** 최고관리자로 승인을 시도하면 403이다 (§12.2).
배포 전에 반드시 변경한다.

## 설계 원칙

### 상태 표현은 서버가 만든다

`status_label`("입법·행정예고")과 `status_caveat`("시행 확정 아님")를 서버가 내려준다.
프론트에서 다시 만들면 웹·텔레그램·이메일의 표현이 갈라지고, "입법예고를 시행 중으로 표시"하는
사고가 채널마다 따로 난다 (AT-04).

### 색이 의미를 나른다

| 색 | 뜻 |
| --- | --- |
| 초록 | 시행 중 (현재 적용 기준) |
| 파랑 | 공포·국회통과 (확정됐으나 시행 전) |
| 호박 | 예고·발의 (**시행 확정 아님**) |
| 빨강 | 유예·폐지·긴급 |

이 대응은 UI 전체에서 흔들지 않는다. 사업자가 색만 보고 판단하기 때문이다.

### 시행일이 없으면 비우지 않는다

`null` 이면 "확인 필요"라고 쓴다. 빈칸은 "없다"로 읽히지만 실제로는
"원문에서 확인하지 못했다"이며, 그 차이가 §10.4가 요구하는 것이다.

### 검수 편집기는 막힌 이유를 보여준다

게이트 판정을 숨기고 승인 버튼만 두면, 검수자가 이유를 모른 채 막히거나
우회 방법을 찾게 된다. 실패한 게이트와 그 결과(BLOCK_APPROVAL 등)를 그대로 노출한다.
